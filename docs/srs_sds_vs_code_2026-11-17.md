# SRS v1.0 and SDS v1.0 compared with the code (17 Nov 2026)

Checked against branch `ayesha/vision-grounding-c`. Nothing in the two documents has been changed yet except the GUI section of the SDS (screenshots, see the end). Every row says what the document says, what the code does, and what to change. "Built" means it works in the app; "Partly" means some of it is there; "Not built" means there is no code for it.

## 1. The six items you asked about

| Item | What the document says | What the code does | Change to make |
|---|---|---|---|
| PyQt6 vs PySide6 | The interface is built with PySide6 (SDS Table 12, DP-1, 5.5.1; SRS SI-12, 2.9). | The app imports PyQt6 in 16 files and `requirements.txt` lists PyQt6. PySide6 is not used anywhere. | Replace "PySide6" with "PyQt6" in the SRS and SDS. (Both are Python wrappers for the same Qt toolkit; PyQt6 is licensed GPL or commercial, PySide6 is LGPL. Mention the licence in the SDS constraints.) |
| Managed backend with row-level security | Accounts, history, saved workflows and progress live in a cloud Postgres database (for example Supabase); each learner can read only their own rows (SDS 3.1, 5.1, 5.6; SRS SI-13, NFR-019, NFR-030). | Everything is in one local SQLite file (`app/db.py`: user, preferences, tutorial, step, session, session_step, conversation, chat_message). Accounts use bcrypt. "Only your own rows" is enforced by the app code filtering on the user id. There is no cloud database and no sync. | Say the shipped build uses the local profile (the documents already allow this as the fallback). Move the backend to "planned" and remove row-level security as a delivered measure. |
| Windows keyring token store | After sign-in a token is kept in Windows Credential Manager through the keyring library (SRS FR-002, SI-15, NFR-024; SDS DP-8, Table 19). | No token is stored. `keyring` is not installed or used. The learner signs in with email and password each time the app opens. | Remove the token store from the shipped design, or build it. Change FR-002 to "login with email and password". |
| Bayesian knowledge tracing (pyBKT) | The dashboard estimates, for each practised operation, the chance it is mastered (SRS FR-056, SDS 5.4.4, SD-14). | Not present. No pyBKT, no mastery, no per-operation record. The Progress page shows counts only: steps done, sessions finished and started, tutorials, chats. | Mark FR-055 and FR-056 as not built. Remove pyBKT from the stack. |
| Staleness check | Before a session starts, compare the tutorial's recorded version with the installed one and warn (FR-045 to FR-047, NFR-018, SDS StalenessChecker, SD-07). | Tutorials keep the version they were recorded in, and the Blender add-on reports the installed version, but nothing compares them and no warning is shown. | Mark FR-046 and FR-047 as not built. FR-045 (read the installed version) is built for Blender. |
| Combining tutorials | Select two or more workflows and merge them with bridging steps (FR-031 to FR-033, UC-LRN-12, SD-06). | Not built. There is no merge code and no screen. `ingestion/scene_chain.py` only checks the order of steps inside one list. | Mark FR-031 to FR-033 as not built. |
| Embedded YouTube player | The session panel plays the video and seeks to the step's time (SRS 2.5, SI-6, CI-7; SDS SessionPanel, Figure 36, SC-11). | Not built. The Find screen has "Open in browser", which opens the link in the default browser. Steps keep video start times but nothing plays them. | Remove the player from the session screen description; say the video opens in the browser. |

## 2. Other differences found

| Area | Document | Code | Change |
|---|---|---|---|
| AI Gateway | Only the gateway holds keys; the client never has them (CI-1, NFR-024, SDS 5.6). Five operations including POST /v1/ground. | A FastAPI gateway exists (`gateway/app.py`) with four operations: /v1/extract, /v1/answer, /v1/youtube/metadata, /v1/youtube/search. There is no /v1/ground. Tokens, counters and the idempotency store are in memory, so it is single-worker only. The desktop app does not use it: it calls Gemini and YouTube directly with keys from a local `.env` file (`app/pipeline.py`, `app/discovery.py`, `app/ask.py`). A `GatewayClient` exists in `ingestion/gateway_client.py` but is not connected to the app. | State that the gateway is built but the app is not yet connected to it, and that keys are currently on the learner's machine. Remove /v1/ground. |
| Where the screen is read | A captured frame is sent to a vision model through the gateway (SI-9, SD-08, SD-09). | Guidance is local. Windows OCR, OpenCV and the Blender add-on's snapshot find the element; nothing about the screen leaves the computer. No vision model is called. | Rewrite SD-08 and SD-09 and the verification order: screen change, then add-on state, then local text reading. This is a privacy gain. |
| Confirmation prompts, mismatch readings, recovery (FR-048 to FR-050) | A prompt asks the learner to confirm when unsure. | Not built. When unsure, no highlight is drawn and the guide box says what is blocking it. | Mark as not built; describe the actual behaviour. |
| Substituting a moved element (FR-051 to FR-053) | Finds the current equivalent and asks to confirm. | FR-051 partly: the grounders report not found, hidden, scrolled out or wrong mode. FR-052 and FR-053 not built. | Update. |
| Consent (FR-001, NFR-029) | Registration records consent to screen capture and sharing. | Not built; no consent screen or record. | Mark as not built, or build it. |
| Profile (FR-004, FR-005, NFR-034) | Applications, level, preferences for warnings, prompts and confidence; export and delete of data. | The profile has display name, theme, a switch for highlighting the target, and change password. | Update. |
| Step labels (FR-028, NFR-014) | Every step shows "drafted automatically" or "reviewed" and a confidence value. | The step editor sets reviewed on edited steps, but the review screen does not show the label or the confidence. | Partly; show them in the UI or change the requirement. |
| Questions (FR-027, FR-043, FR-044) | Answers carry documentation references; a question box is on the session panel. | Ask GuideWire answers from the knowledge base and, with a key, a model. The answer text mentions its source, but there is no references list. The session screen only has "Ask about this tutorial", which opens the Ask screen. | Partly. |
| Progress and history (FR-007 to FR-009, FR-054) | Progress events; a dashboard. | Sessions and step states are saved after every change (NFR-039 met). History lists sessions with Start again, Continue and Review. Progress is partly built (counts). | Update. |
| Status by icon and word (NFR-042), keyboard access (NFR-041) | Required. | Not checked. | Check, or mark unverified. |
| Class names (SDS 1.5 says names match the code) | AppController, EngineFacade, SessionStore, GuidanceLoop, ChangeDetector, Verifier, Grounder, ConfirmationPrompt, TokenStore, LibraryService, ProgressTracker, BackendRepository, WorkflowMerger and others. | Of these, only SessionEngine, GatewayClient, OverlayWindow (in `vision/overlay.py`), LLMProvider and GeminiProvider exist. | Add a table mapping each design class to the real module, for example Router to `ingestion/router.py`, Grounder to `vision/grounders.py`, Verifier to `vision/verify.py`, ChangeDetector to `vision/scene.py`, TutorialDiscovery to `app/discovery.py` and `ingestion/tutorials.py`, and platform layer to `vision/winplatform.py` and `vision/capture.py`. |
| Probes for Maya and Houdini | Read-only probes for all three. | Probe files exist for Maya and Houdini (`vision/probes`), but the interface catalogue and the live checks of the highlight exist for Blender only; the Houdini real-application tests cannot run here (no licence). | Say Blender is checked, Maya and Houdini are prototypes. |
| Data retention (NFR-025, NFR-026) | Cached rows carry fetched_at and expires_at and a scheduled job deletes expired ones. | A 30-day purge of cached extractions, run logs and captions exists, driven by file age (`ingestion/retention.py`, `cli purge`), and is not a scheduled job. | Describe it as file-based and manual. |
| Tests (SDS 7) | Test cases to be written in FYP-II. | About 1,400 automated tests, ruff, mypy and pytest in CI. | Update. |
